# 分组详情页与新对话校验 —— 开发指引

> 角色：AI 产品经理 × 交互设计专家
> 适用范围：crop-agent-web（Vue 3 + Pinia + Element Plus）/ crop-agent-server（FastAPI + SQLAlchemy）
> 目标：修复「分组内多对话在侧边栏内联展开，层级混乱、空间不足」与「新建对话失败无提示」两个体验问题

> ⚠️ **最新迭代变更（以本区块为准，正文部分章节已被取代）**
> 1. **新增对话只在历史记录**：`newChat()` 已去掉 `groupId` 参数，不再创建到分组内；分组详情页已**移除「新建对话」按钮**（正文 2.2 / 2.4 / 1.3 决策表 D2 的分组内创建方案已失效，保留仅作历史参考）。
> 2. **历史区空对话规则（类似千问）**：点「新建对话」时，历史记录存在空对话（`message_count === 0` 且未分组）→ 第一次**复用**并进入；已被复用的同一空对话再次触发 → **禁止新建**并提示「已存在未使用的空对话，请先使用或清理后再新建」（单例提示：连点不叠加、**不显示点击次数角标**，不使用 `grouping`/`repeatNum`）；空对话条目常驻「**未使用**」标签（文字提示形式为用户选定的唯一形式，无顶部横幅）。
> 3. **新增批量管理**：历史区与分组详情页均可进入批量模式（勾选/全选）→ 批量删除、批量移动分组（含移出分组），复用 `store.batchDelete` / `store.assignSessions`，后端零改动；实现为 `src/composables/useBatchSelection.ts` + `src/components/BatchActionBar.vue`。分组详情页批量移动时**排除当前分组**（`moveGroups` 过滤），历史区仍列出全部分组。
> 4. 后端 `POST /api/sessions` 的可选 `group_id` 与空对话兜底校验保留（向后兼容，前端不再使用）。

## 一、需求理解与产品决策

### 1.1 现状问题（代码事实）

- `AppSidebar.vue` 中分组区（`.groups`）目前把分组内会话**内联展开**在侧边栏（`.sec-head.is-group` + `.sec-items`），分组多、会话多时层级深、空间挤。
- `newChat()`（`stores/chat.ts`）已按上一轮需求改为「复用空对话或创建」，全局不再弹「空对话」提示——但**分组上下文下没有校验**，用户不知道新对话是否创建成功、创建到哪了。

### 1.2 目标交互（参考通义千问）

```
┌────────────┬─────────────────────────────────────┐
│  侧边栏     │  主内容区：分组详情页 /group/:id       │
│ ─────────  │  ┌─────────────────────────────────┐ │
│ 对话分组    │  │ ← 返回     📁 水稻种植   (3)     │ │
│  📁 水稻种植│  │ [重命名] [删除]   [＋ 新建对话]   │ │
│  📁 病虫害  │  ├─────────────────────────────────┤ │
│ ─────────  │  │ 🔍 搜索对话…（实时模糊过滤）      │ │
│ 历史对话    │  ├─────────────────────────────────┤ │
│ …          │  │ 🗨 水稻稻瘟病怎么防治？   ⋯       │ │
│            │  │ 🗨 氮肥用量多少合适？     ⋯       │ │
└────────────┘  └─────────────────────────────────┘ │
```

- 点击侧边栏分组 → **不再展开子列表**，导航到右侧详情页；
- 详情页顶部搜索框对**对话名称**做**实时模糊过滤**；
- 详情页内的「新建对话」= **在当前分组内创建**，并执行「空对话」校验。

### 1.3 关键产品决策（已定，开发按此执行）

| # | 决策 | 说明 |
|---|------|------|
| D1 | 侧边栏分组只做导航入口 | 移除分组内联展开（chevron、`.sec-items`），分组行 = 可点击导航项，右侧渲染详情页 |
| D2 | 分组内新建 = 归属该分组 | 新会话携带 `group_id` 创建，出现在该分组的详情列表中，闭环可见 |
| D3 | 「空对话」校验范围 = 当前分组 | `message_count === 0`（无任何问答记录）且**非置顶**（置顶会话在「置顶」区展示，不参与分组） |
| D4 | 全局新建对话不拦截 | 无分组上下文时维持上一轮「复用或创建」行为（`stores/chat.ts` 现有逻辑），避免回到"全局反复弹窗"老问题 |
| D5 | 拦截提示文案精确使用需求原文 | `已存在未使用的空对话，请先使用或清理后再新建`，`ElMessage.warning` + `grouping: true` 防重复叠加 |
| D6 | 服务端兜底校验 | `POST /api/sessions` 带 `group_id` 时服务端同样校验空对话（防多端/绕过前端），返回同文案 400 |
| D7 | 置顶会话不进分组详情列表 | 与 `utils/history.ts` 的 `buildHistorySections` 规则保持一致（`!s.pinned && s.group_id === g.id`） |

> 待确认项（默认方案，可讨论）：**侧边栏顶部「新建对话」在 `/group/:id` 页时按「当前分组」处理**（带分组校验、创建到该分组）；不在分组页时按全局处理。若希望顶部按钮永远全局，仅需去掉 AppSidebar 的传参。

### 2.2 新增视图 `src/views/GroupDetailView.vue`（核心交付物）

结构：**页头（返回 + 分组名 + 会话数 + 分组操作 + 新建对话）→ 搜索框 → 会话列表/空态**。

关键实现（骨架，可直接落盘）：

```vue
<script setup lang="ts">
import { computed, ref, watch } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { useChatStore } from '@/stores/chat'
import { useHistoryManager } from '@/composables/useHistoryManager'
import SessionActionMenu from '@/components/SessionActionMenu.vue'

const route = useRoute()
const router = useRouter()
const store = useChatStore()
const { onRenameGroup, onDeleteGroup } = useHistoryManager() // 复用侧边栏同名能力

const keyword = ref('')                       // 搜索关键词
const gid = computed(() => Number(route.params.id))
const group = computed(() => store.groups.find((g) => g.id === gid.value))

/** 分组内会话：非置顶（置顶在「置顶」区）；store.sessions 已按置顶+创建时间排序 */
const items = computed(() =>
  store.sessions.filter((s) => !s.pinned && s.group_id === gid.value),
)

/** 需求一：按对话名称实时模糊过滤（小写 + 包含匹配） */
const filteredItems = computed(() => {
  const kw = keyword.value.trim().toLowerCase()
  if (!kw) return items.value
  return items.value.filter((s) => (s.title || '').toLowerCase().includes(kw))
})

/** 需求二：分组内新建对话（校验逻辑在 store.newChat 内） */
async function onNewChatInGroup() {
  const ok = await store.newChat(gid.value)
  if (ok) router.push({ path: '/chat' })      // 进入新会话（欢迎页）
}

function onOpenSession(id: string) {
  router.push({ path: '/chat', query: { session: id } }) // 与侧边栏一致
}

/** 切换分组时清空搜索词 */
watch(() => route.params.id, () => { keyword.value = '' })

const missing = computed(() => !group.value)  // 分组被删/不存在 → 兜底态
</script>

<template>
  <div class="group-detail">
    <!-- 页头 -->
    <header class="gd-head">
      <button class="gd-back" title="返回" @click="router.push('/chat')">
        <el-icon><Back /></el-icon>
      </button>
      <div class="gd-title">
        <h1>{{ group?.name ?? '分组详情' }}</h1>
        <span class="gd-count num">{{ items.length }} 个对话</span>
      </div>
      <div class="gd-actions">
        <button class="gd-btn" @click="onRenameGroup(gid)"><el-icon><EditPen /></el-icon>重命名</button>
        <button class="gd-btn danger" @click="onDeleteGroup(gid)"><el-icon><Delete /></el-icon>删除</button>
        <button class="gd-new" @click="onNewChatInGroup">
          <el-icon><Plus /></el-icon>新建对话
        </button>
      </div>
    </header>

    <!-- 搜索框：实时过滤 -->
    <div class="gd-search">
      <el-input
        v-model="keyword"
        placeholder="搜索对话"
        clearable
        :prefix-icon="Search"
      />
    </div>

    <!-- 列表 / 空态 -->
    <div class="gd-list">
      <div v-if="missing" class="gd-empty">分组不存在或已被删除</div>
      <div v-else-if="!filteredItems.length" class="gd-empty">
        {{ keyword.trim() ? `未找到与「${keyword.trim()}」相关的对话` : '暂无对话，可在对话「操作」菜单中移入' }}
      </div>

      <div
        v-for="s in filteredItems"
        :key="s.session_id"
        class="gd-item"
        :class="{ active: s.session_id === store.activeSessionId }"
        @click="onOpenSession(s.session_id)"
      >
        <span class="gd-ico"><el-icon><ChatDotRound /></el-icon></span>
        <div class="gd-main">
          <div class="gd-name">{{ s.title }}</div>
          <div class="gd-meta">
            <span v-if="s.message_count === 0" class="gd-tag">未使用</span>
            <span class="gd-msg">{{ s.message_count ?? 0 }} 条消息</span>
          </div>
        </div>
        <SessionActionMenu :session="s" />
      </div>
    </div>
  </div>
</template>
```

要点：
- 列表**直接响应 store 数据**（`store.sessions` / `store.groups`），移入/移出/删除/重命名后由 `loadSessions()` 触发自动刷新，无需本地维护副本；
- 「未使用」标签为可选项（帮助用户理解为何新建被拦截），不强制；
- `SessionActionMenu` 天然支持「移出分组」「删除此对话」，满足详情页内的会话管理；
- 样式复用现有设计变量（`--crop-green`、`--radius-card`、`--radius-pill`），参考 `ChatView.vue` 页头与 `AppSidebar.vue` 条目样式。

### 2.4 状态层 `src/stores/chat.ts` —— `newChat(groupId?)`

在现有 `newChat` 上扩展分组校验（不改变全局行为）：

```ts
async function newChat(groupId?: number): Promise<boolean> {
  if (creatingSession.value) return false          // 防重复触发（保留）
  if (isStreaming.value) {
    ElMessage.info({ message: '正在生成回答，请稍候再新建', grouping: true })
    return false
  }
  creatingSession.value = true
  try {
    // 需求二：分组上下文 → 校验「当前分组下」是否存在未使用的空对话
    if (groupId != null) {
      const empty = sessions.value.find(
        (s) => s.group_id === groupId && !s.pinned && s.message_count === 0,
      )
      if (empty) {
        ElMessage.warning({
          message: '已存在未使用的空对话，请先使用或清理后再新建',
          grouping: true,                          // 连点不叠加弹窗
        })
        return false                               // 禁止创建，不跳转
      }
    }
    // 全局上下文 → 复用任意空对话（维持上一轮行为，不拦截）
    if (groupId == null) {
      const empty = sessions.value.find((s) => s.message_count === 0)
      if (empty) {
        messages.value = []; error.value = ''; lastQuery.value = null
        activeSessionId.value = empty.session_id
        await loadSessions()
        return true
      }
    }
    // 创建新会话：分组内创建 → 携带 group_id 归属当前分组
    messages.value = []; error.value = ''; lastQuery.value = null
    activeSessionId.value = null
    try {
      const res = await api.createSession(groupId)
      activeSessionId.value = res.data.data.session_id
      await loadSessions()
    } catch { /* 后端不可用：保持本地空白态，首条消息兜底建会话 */ }
    return true
  } finally {
    creatingSession.value = false
  }
}
```

### 3.2 `api/chat.py` —— `create_session` 支持 group_id + 服务端兜底

```python
from db.schemas import SessionCreateRequest  # 加入导入

@router.post("/api/sessions", response_model=ApiResponse)
def create_session(req: SessionCreateRequest | None = None, db: Session = Depends(get_db)):
    """创建会话；带 group_id 时归属该分组，并校验分组内无「未使用的空对话」。"""
    payload = req or SessionCreateRequest()
    gid = payload.group_id
    sid = uuid.uuid4().hex

    if gid is not None:
        g = db.query(SessionGroup).filter(SessionGroup.id == gid).first()
        if not g:
            return ApiResponse.fail("分组不存在", code=404)
        # 服务端兜底：分组内存在 0 消息会话 → 拒绝创建（与前端同文案）
        group_sids = [
            s.session_id
            for s in db.query(SessionModel).filter(SessionModel.group_id == gid).all()
        ]
        if group_sids:
            counts = dict(
                db.query(Message.session_id, func.count(Message.id))
                .filter(Message.session_id.in_(group_sids))
                .group_by(Message.session_id)
                .all()
            )
            if any(counts.get(sid2, 0) == 0 for sid2 in group_sids):
                return ApiResponse.fail(
                    "已存在未使用的空对话，请先使用或清理后再新建", code=400
                )

    db.add(SessionModel(session_id=sid, title="新对话", group_id=gid))
    db.commit()
    return ApiResponse.ok({"session_id": sid})
```

兼容性：`req` 带默认值 `None`，不传 body 的旧调用（当前前端全局新建）完全兼容。

## 四、边界情况与异常处理

| 场景 | 处理 |
|------|------|
| 分组不存在 / 已删除（详情页） | 页头兜底态「分组不存在或已被删除」，可返回 /chat；侧边栏分组行随之消失 |
| 分组内无会话 | 空态：「暂无对话，可在对话「操作」菜单中移入」 |
| 搜索无结果 | 空态：「未找到与「关键词」相关的对话」；清空搜索恢复全量 |
| 组内存在空草稿时点「新建对话」 | `ElMessage.warning` 精确文案，**不创建、不跳转**；提示后停留在详情页 |
| 空草稿发了首条消息 | `message_count ≥ 1`，校验放行，可再新建 |
| 空草稿被删除 / 移出分组 | 校验放行（移出后归全局/日期区，不再算组内空对话） |
| 从其他分组/全局把空对话移入本组 | 移入后即视为组内空对话，下次新建被拦截（符合「当前分组下」语义） |
| 置顶的空对话 | 置顶会话不参与分组展示与校验（D7） |
| 流式生成中新建 | 保留现有 `isStreaming` 提示，不执行创建 |
| 连点/双击「新建对话」 | `creatingSession` 防重入 + `grouping: true`，提示至多一次、请求至多一次 |
| 后端不可用 | 保持本地空白态，首条消息经 WS/REST 兜底自动建会话（现有行为） |
| 全局（非分组页）新建 | 复用或创建，不弹「空对话」提示（D4，衔接上一轮需求） |

## 五、验收标准

### 需求一：分组详情页
- [ ] 点击侧边栏分组，侧边栏**不展开**子列表，右侧主区渲染 `/group/:id` 详情页
- [ ] 详情页以列表/卡片展示该分组下全部对话（非置顶），点击会话进入对应对话
- [ ] 顶部搜索框输入关键词，按**对话名称**实时模糊过滤；清空/清除按钮恢复全量
- [ ] 空分组与搜索无结果均有明确空态文案
- [ ] 分组重命名 → 详情页标题同步；删除分组 → 详情页显示兜底态，会话回到日期区
- [ ] 详情页内「移出分组 / 删除对话」后列表即时刷新
- [ ] 侧边栏当前分组高亮与路由联动；移动端抽屉行为一致

### 需求二：新建对话校验
- [ ] 分组内无空对话时点「新建对话」→ 创建成功，新会话**出现在该分组**并进入对话页
- [ ] 分组内存在 `message_count === 0` 的空对话时点「新建对话」→ 弹出 `已存在未使用的空对话，请先使用或清理后再新建`，**不创建**
- [ ] 对该空对话发送首条消息后，再点「新建对话」→ 放行
- [ ] 删除该空对话后，再点「新建对话」→ 放行
- [ ] 连点两次 → 提示不叠加、请求不重复
- [ ] 全局（历史对话/聊天页）点「新建对话」→ 维持复用或创建，**不**弹此提示
- [ ] 直接调 `POST /api/sessions`（body 带 group_id，组内有空对话）→ 400 + 同文案（服务端兜底）

## 七、风险与建议

- **双端校验一致性**：前端拦截是体验层，服务端校验是数据一致性保障；两者共用同一文案，改动需同步。
- **空草稿堆积**：全局新建采用「复用」策略（上一轮需求），分组新建采用「拦截」策略——语义差异需在后续迭代中评估是否统一（例如改为分组内自动复用空草稿）。
- **可选增强**：详情页空草稿显示「未使用」角标（本指引骨架已含）；搜索框支持高亮命中的关键词片段。
- **建议清理**：`App.vue` 的 `/history` 导航为死链（路由未注册、HistoryView 已不存在），与本次需求无关，可顺带移除。
